# MagGrad 通信重构与可复用 ROS 串口包方案

> 汇报对象：项目同事与负责人  
> 状态：固件通信协议 v2 和调试接收脚本已实现；ROS 串口包仍处于设计阶段  
> 日期：2026-09-28

## 一页摘要

本次改动把单片机原先“每个传感器各发一帧、上位机再猜测哪些帧属于同一轮”的通信方式，改为**主循环每轮生成一个 ROUND 帧，并通过 USB CDC 发送一次**。同一帧包含当轮可用的 AK、TMAG、ICM 数据，以及 PHASE、错误和周期统计记录。每条传感器记录带相对轮首的微秒级读取完成偏移；整轮只有一份序号、微秒时间和 CRC。

这个改动直接给上位机提供清晰的轮边界，减少重复帧头和 CDC 发送调用。按所有传感器均有有效数据、且不计低频 ERR/STATS 与 USB 开销估算，默认 12 路 TMAG 配置从 **340 B/轮降为 235 B/轮**；12 路 AK、12 路 TMAG、ICM 全开时从 **694 B/轮降为 472 B/轮**，应用层字节数约减少三成。这是协议结构的理论估算，实际轮频和吞吐仍需台架测量。

后续计划把串口读取、协议解析、整轮数据模型与 ROS 发布分层：底层 C++ 库不依赖 ROS，先接入 ROS Noetic，迁移 ROS 2 时复用底层，只替换适配层。目前尚未实现正式 ROS 包。

## 背景与目标

旧协议 v1 为每条 AK/TMAG/ICM 数据及 PHASE、ERR、STATS 分别封帧和发送。上位机需要通过 PHASE 帧推断一轮结束；一轮中任意子帧丢失或到达顺序异常，都可能让周期聚合变复杂。各帧重复携带同步字、版本、序号、时间、长度和 CRC，USB 发送调用次数也随传感器数量增加。

本轮讨论确定了三个目标：

1. 单片机正常遥测每轮恰好一个应用协议帧，主循环明确负责整轮聚合。
2. 尽量保持现有传感器读取函数接口，避免重写 AK、TMAG、ICM 驱动。
3. 为高频、可复用的 ROS 串口接收包提供明确的轮边界和可独立验证的协议层。

## 已完成：固件通信重构

| 项目 | 实现与效果 |
| --- | --- |
| 整轮构帧 | 主循环采样轮首 TIM2 计数作为 `tick_us`，并用同一快照计算读取完成偏移，依次向同一缓冲区追加传感器记录、PHASE、可能发生的 ERR 和到期的 STATS，最后填长度、计算一次 CRC、调用一次 `USB_Send_Raw()`。 |
| v2 帧头 | `A5 5A | version=2 | type=0x10 | round_seq:u32 | tick_us:u32 | payload_len:u16`；帧尾为 CRC-16/CCITT-FALSE。多字节字段均为小端。 |
| 可扩展记录 | 帧内记录为 `type:u8 | len:u16 | body`。接收端可按长度跳过未知类型。现有传感器函数继续调用 `BinaryWriter_AppendFrame()`，该函数现在追加记录而非独立帧。 |
| 时间信息 | AK、TMAG、ICM 记录在原内容前加入 `read_done_offset_us:u32`，由追加记录时的 TIM2 计数减去轮首计数得到，按 32 位无符号数处理回绕。它表示**读取完成时间**，不表示传感器内部转换完成时间。PHASE、ERR、STATS 不带此偏移。 |
| 失败处理 | 任何追加或封帧失败都会丢弃整个轮帧；`round_seq` 仍前进，便于接收端发现缺轮。USB 发送现区分 `USBD_OK`、`USBD_BUSY` 和 `USBD_FAIL`；发送失败累计计数会在后续成功送达的 ERR 记录中报告。 |
| 日志隔离 | 二进制模式的 `printf` ASCII 日志走 USART1，不再混入 USB 二进制流；CSV 调试模式保留。 |

协议版本升至 **v2**；旧 v1 接收程序需同步升级。完整字段定义见[通信协议](host_device_communication_protocol.md)。

### 上位机调试支持

`tools/usb_read.py` 已按 v2 更新：从任意字节位置搜索帧头，按长度等待整轮，校验版本、类型和 CRC，再按记录长度解析；遇到未知记录可以跳过，CRC 错误后重新同步。脚本可统计整轮频率、各传感器记录数和序号跳变。它是协议调试工具，尚不是正式 ROS 驱动。

## 未来方案：可复用 ROS 串口包

计划把设备接入做成可独立复用的组件，而不是把串口、协议和 ROS API 写进同一个节点：

```text
/dev/maggrad
    │  Boost.Asio 异步串口读取、断线重连
    ▼
Transport（只处理字节流和连接状态）
    ▼
Protocol（同步字、长度、CRC、v2 记录解码、时间展开）
    ▼
有界整轮队列（慢订阅者不阻塞串口读取）
    ▼
ROS 适配层（Noetic：roscpp；ROS 2：rclcpp）
    ├── /maggrad/sample
    └── /diagnostics
```

分层边界建议如下：

| 层 | 职责 | 复用方式 |
| --- | --- | --- |
| `maggrad_protocol` | 纯 C++14 的流解析、CRC、记录解码、轮序号检查、设备时间展开和测试；不包含 ROS 头文件。 | ROS 1、ROS 2、命令行录制/回放工具共用。 |
| `maggrad_transport` | Boost.Asio 异步读取、设备发现/稳定路径、拔插重连、接收统计；不理解具体传感器字段。 | 可复用到其他 CDC/串口设备，协议解析器按需替换。 |
| `maggrad_driver_ros1` / `maggrad_driver_ros2` | 从有界队列取完整轮，转换消息，发布 `/maggrad/sample` 与 diagnostics。 | 两套薄适配层保持消息语义一致。 |

关键运行约束：I/O 回调只读取、解析和入队，不同步发布 ROS 消息或写磁盘；队列满时丢旧轮并计数，防止慢订阅者反向阻塞串口。解析器必须接受任意拆包、粘包和噪声。`round_seq` 空洞用于识别整轮缺失；记录缺失则由未就绪、未启用或访问错误等原因单独标记。设备 `tick_us` 与每条读取完成偏移都应保存在消息中，主机时间映射可后续校准。详细设计见[ROS 接收方案](host_ros_high_rate_receiver_design.md)。

## 建议实施顺序与验收点

1. **完成固件台架确认。** 默认和全传感器配置分别持续运行，记录有效轮频、序号空洞、CRC 错误、USB 发送失败及主机接收字节率；验证长时间稳定性。
2. **先做不依赖 ROS 的核心库和回放测试。** 用已录制的 v2 字节流验证拆包、错误恢复、未知记录、设备重启与时间回绕，并定义稳定的整轮数据结构。
3. **实现异步传输与无 ROS 压测工具。** 检查高负载持续接收、慢消费者、断线重连和内存上限。
4. **接入 ROS Noetic。** 发布整轮样本和诊断，测量主机侧发布延迟与队列丢轮；再冻结消息接口。
5. **迁移 ROS 2。** 复用协议与传输层，用相同录制流比对 ROS 1/ROS 2 输出，并按高频数据选择合适的 QoS。

本阶段需要的决策主要是：确认 v2 作为后续唯一接收协议；明确全传感器目标轮频及可接受的丢轮/延迟指标；确定 ROS 消息中哪些原始字段必须长期保持兼容。
