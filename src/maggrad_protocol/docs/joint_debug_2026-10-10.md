# MagGrad 上下位机联合调试实验记录（2026-10-10）

## 1. 实验目的与范围

确认连接的 STM32 是否被上位机识别、是否持续发送符合 MagGrad v2 协议的 ROUND 帧，以及串口桥接、协议解码和统计节点能否组成完整 ROS 接收链路。

本次只读取设备输出，没有发送下行控制命令，没有修改或检查下位机固件，也没有测量传感器供电、总线波形和外部 PHASE 信号。因此，本文区分**已观测事实**与**待验证的原因推测**，不将短时串口通信成功等同于传感器采集成功。

## 2. 环境与测试方法

### 2.1 设备接口

| 项目 | 本次结果 |
| --- | --- |
| 系统 | Ubuntu 20.04 系列环境，ROS Noetic |
| STM32 接口 | `/dev/ttyACM1`，USB CDC 虚拟串口 |
| 稳定设备路径 | `/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_315E39623233-if00` |
| 上位机打开参数 | 115200 波特率 |
| STATS 中的设备 ID | `3063479653` |

系统同时存在 `/dev/ttyACM0`（ArcField Controller）和 `/dev/ttyUSB0`（USB Serial），本次没有使用这两个接口。联合 launch 默认使用上述 STM32 的稳定路径，避免设备枚举顺序改变后选错串口。

注意：USB CDC 的实际传输速度不能仅由上位机设置的 115200 推断。是否使用 CDC line coding 配置、是否存在后级 UART，仍需根据固件实现确认。

### 2.2 测试步骤

1. 检查设备节点和 `/dev/serial/by-id/` 标识。
2. 使用独占方式短时读取 STM32 串口，对完整 ROUND 帧检查同步头、版本、类型、长度与 CRC。
3. 对后续约 2 秒的数据按协议解析 TLV 类型、传感器 ID、PHASE 和 STATS。
4. 构建两个功能包，运行既有协议/串口测试及新增统计测试。
5. 在独立 ROS master（端口 11329）上短时启动 `joint_debug.launch`，验证：

   ```text
   STM32 → serial_frame_bridge → maggrad_protocol → statistics_node
   ```

6. 在订阅建立后观察约 5 秒的样本与统计消息，随后停止本次测试节点并释放串口。

使用独立 master 是为了隔离此次调试；日常启动不需要指定该端口。此次没有进行长时间运行、热拔插或有效传感器数据的吞吐测试。

## 3. 已观测到的现象

### 3.1 串口与帧校验正常

首次约 4 秒读取获得 1,073,152 字节、34,614 个有效 ROUND，未发现 CRC 错误或非法帧头。该阶段用于确认字节流与整帧协议，不作为传感器记录类型的判断依据。

后续更详细的一次探测结果如下：

| 指标 | 结果 |
| --- | --- |
| 读取时间 | 约 2.039 秒 |
| 接收字节数 | 532,480 |
| 完整且 CRC 正确的 ROUND 数 | 17,175 |
| CRC 错误数 | 0 |
| 首个完整帧的序号 / tick | `38399 / 462096 ms` |
| 最后完整帧的序号 / tick | `55573 / 464099 ms` |
| PHASE TLV | 17,175 条，类型 `0x04`，长度 12 字节 |
| STATS TLV | 2 条，类型 `0xF0`，长度 24 字节 |
| AK / TMAG / ICM TLV | 均未发现 |
| ERR TLV | 未发现 |

这次探测的完整帧数量等于末序号减首序号加一，且 tick 前进约 2 秒，未见这段完整帧序列的数量缺口。串口读取窗口边缘可能包含半帧，不计入完整帧数量。

### 3.2 有大量 ROUND，但没有有效传感器记录

- ROUND 持续发送，直接探测中所有 ROUND 都带 PHASE。
- 没有 AK、TMAG 或 ICM 记录，无法据此识别实际传感器 ID，也没有磁场、加速度或角速度数据可用于评估。
- PHASE 三路年龄值全部为 `0xFFFFFFFF`，按当前协议表示无效。
- 直接探测累计得到 51,525 个无效 PHASE 值，恰好为 `17,175 × 3`。

因此，**高 ROUND 频率只说明协议轮次发送很快，不代表传感器有效采样频率很高**。

### 3.3 固件 STATS 显示传感器计数为零、存在累计错误

直接探测的两条 STATS 均为：

| 字段 | 值 |
| --- | --- |
| `ak_frames` | 0 |
| `tmag_frames` | 0 |
| `icm_frames` | 0 |
| `skipped` | 0 |
| `errors` | 3778 |
| `device_id` | 3063479653 |

后续联合测试的最近 STATS 中，三个传感器计数和 `skipped` 仍为 0，`errors` 为 5176。

两个观察阶段之间累计错误数增加了 1398，但两次 STATS 不属于同一个固定时间窗口，不能据此计算错误频率。直接探测的两条 STATS 相同，也不能认定每个 ROUND 都发生一次传感器错误。

没有收到 ERR TLV，故上位机没有可用于定位故障的 `source/code/detail`。累计 errors 非零而没有 ERR 记录并不矛盾：错误可能来自之前的初始化、固件仅累计计数而不逐项发送错误记录，或具体错误记录在其他时刻发送；需要检查固件才能确定。

### 3.4 ROS 联合接收与统计链路成功，但存在序号缺口

`joint_debug.launch` 成功启动三个节点。检查订阅端约 5 秒内收到 41,213 条 `RoundSample` 和 5 条统计消息。最后一个样本仍为 AK 数量 0、TMAG 数量 0、`has_icm=false`。

最近一次统计报告的关键值为：

| 指标 | 值 |
| --- | --- |
| ROUND 频率 | 约 8281.61 Hz |
| 统计节点累计 ROUND 数 | 55,332 |
| 本周期 AK / TMAG / ICM 记录数 | 全部为 0 |
| 本周期无效 PHASE 值数 | 24,846 |
| 解码器累计有效帧数 | 55,370 |
| 解码器累计 `seq_holes` | 2323 |
| 解码器 CRC 错误 | 0 |
| 桥接累计有效帧数 | 60,146 |
| 桥接 CRC 错误 | 0 |
| 桥接 `rx_queue_dropped` | 0 |
| 桥接与解码诊断是否可见 | 均可见 |
| 统计诊断等级 | WARN |

WARN 与本周期 PHASE 无效、默认未配置预期传感器以及上游异常诊断相符，并非统计节点无法接收数据。

各节点的计数来自异步发布、不同采样时刻，启动订阅建立时间也不同。不能直接用桥接计数减解码计数、或解码计数减统计计数作为精确丢帧量。

### 3.5 默认 `complete=true` 不证明硬件完整

本次 `expected_ak`、`expected_tmag` 均为空，`expect_icm=false`。解码器在没有任何预期传感器时，即使 ROUND 没有传感器记录，也会得到 `complete=true`。

该字段目前只能说明“未缺少配置中要求的记录”，不能作为采集成功的依据。实际传感器 ID 未确认前，本次没有自动填充预期配置，也没有开启 `expected_configured=true`。

## 4. 可能原因与验证方法

以下原因均为推测，不是已定位的故障。

### 4.1 优先排查：传感器硬件或初始化失败

**依据：** 三类传感器记录及固件计数均为零，固件存在累计错误，而 USB 帧输出正常。

可能原因包括：传感器供电或共地异常、线缆/连接器问题、总线外设未初始化、器件地址或片选配置错误、复位或工作模式设置失败，以及固件使用了与实际板卡不匹配的硬件配置。

**验证方法：** 检查电压与连接；读取器件身份寄存器；检查 I²C 地址应答或 SPI 片选/时序；记录每类传感器初始化返回值及总线错误码。先验证一个器件能稳定返回原始数据，再扩展到完整阵列。

尚未确认实物的具体传感器型号和数量，不应仅凭“所有记录为零”断言三类器件同时损坏。

### 4.2 采集任务、DRDY 或中断路径没有产出数据

**依据：** 通信任务能够运行，但没有采集结果进入 ROUND。

可能存在采集任务未启用、DRDY 极性或引脚映射错误、定时器/中断未触发、任务同步条件一直不满足、采集队列未写入或记录打包分支未执行等问题。固件也可能处于仅输出状态而未启用采集的模式。

**验证方法：** 分别增加任务循环、DRDY/中断触发、读取成功、读取失败、队列入队和 TLV 打包计数，定位数据在哪一层消失。本次上位机没有发送启动采集命令；是否需要额外使能，必须由固件行为或文档确认，不能试发未知命令。

### 4.3 PHASE 输入未连接或时间戳未更新

**依据：** 所有 PHASE 年龄值均为无效哨兵值，而不是一个有效但较大的年龄。

可能原因包括外部相位/同步输入缺失、输入捕获引脚或边沿配置错误、捕获中断未执行，或该运行模式本来就没有提供 PHASE。

**验证方法：** 确认当前模式是否要求三路 PHASE；测量输入波形；检查捕获次数与最近捕获时间；核对有效标志及年龄计算逻辑。PHASE 无效与传感器无记录可能是两个独立问题，不能未经验证就建立因果关系。

### 4.4 无数据时仍高速发送空采集轮次

**依据：** ROUND 约 8.3 kHz，负载主要只有 PHASE；每帧通常只有 15 字节负载、31 字节整帧，没有传感器记录。

可能是主循环在没有有效采集结果时仍不断递增序号并发送 ROUND，或采集失败后没有等待下一采样周期。短帧高频发送会增加 ROS 消息数量和调度压力，但并不提高有效数据量。

**验证方法：** 对比配置的采集周期、实际成功读取次数和 ROUND 发送次数；检查空轮次发送条件与限频逻辑。是否应该限频、等待数据或仅发送低频状态，需要根据系统设计决定，不应仅为了让上位机统计更好看而改变协议行为。

### 4.5 序号缺口可能来自固件或 ROS 队列，而不一定来自串口

**依据：** ROS 联合测试的 `seq_holes=2323`，但桥接 CRC 错误与内部 RX 队列丢弃均为 0；短时直接串口探测未见完整帧序列的数量缺口。

当前桥接原始帧和解码样本的 ROS 发布队列深度均为 5。约 8.3 kHz 的消息频率、批量发布、调度抖动或消费者处理不及时可能使 ROS 发布/传输/订阅路径出现丢弃。桥接的 `rx_queue_dropped` 只统计桥接内部队列，不覆盖全部 ROS 队列，因此其为零不能排除 ROS 层丢帧。

其他可能性包括固件在实际发送前就递增序号、固件发送失败或不同阶段负载变化。CRC 为零也不能排除整帧未到达：校验只覆盖已经接收到的完整帧。

**验证方法：** 同一测试窗口逐段记录帧序号，比较设备发送、桥接接收、协议接收和样本接收；分开统计各段缺口；用可控速率测试队列和处理能力。直接串口读取与 ROS 串口节点应分时运行，避免两个进程同时读取同一接口。

## 5. 建议的下一轮实验顺序

1. **先解决“无传感器数据”**：确认实物配置、供电、器件应答和初始化状态；获取固件具体错误来源。
2. **验证单器件采集闭环**：确认读取成功计数增长，并出现对应 AK/TMAG/ICM TLV，检查数据随刺激变化。
3. **单独验证 PHASE**：确认是否为当前模式必需；如需要，验证输入、捕获与年龄有效性。
4. **确认采集与发送节拍**：区分有效采样频率、ROUND 频率及状态消息频率。
5. **配置实际预期 ID**：填写 `expected_sensors.yaml`，再设置 `expected_configured=true`，观察缺失传感器与完整比例。
6. **最后定位序号缺口与吞吐瓶颈**：在有意义且可控的采集频率下做逐段序号对照和长时间运行测试。

## 6. 总结与验证边界

**本次已确认 USB 串口和 v2 帧通信能够工作，ROS 桥接、解码和统计链路能够运行；未确认传感器采集正常。** 当前最重要的异常是“高频 ROUND、零传感器记录、PHASE 全无效、固件累计错误非零”，其次是 ROS 联合测试中出现序号缺口。

两个功能包构建成功，协议解码、统计累加、帧解析和伪终端串口测试共 4 个 CTest 测试通过。这些测试与短时实物通信只能验证已覆盖的软件行为，不能证明硬件供电、总线初始化、实际采样精度、持续吞吐和热拔插恢复正常。

本次 ROS 测试日志保存于 `/tmp/maggrad_joint_debug.log`，属于临时文件，不是持久实验归档。本文记录的是当次观察值；后续设备状态和计数可能改变，定位原因仍需下位机日志与硬件测量。
